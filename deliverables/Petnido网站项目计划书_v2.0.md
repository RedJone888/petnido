## 1. 项目概述

Petnido 是一个连接宠物主人与宠物照护服务者的平台。同一账号既可以发布宠物照护需求，也可以开启接单模式、建立服务档案并发布多个服务。

平台围绕三类业务建立统一撮合体系：

- 上门照护；
- 宠物寄养；
- 自定义服务。

游客可以浏览公开需求、服务者和服务；收藏、咨询、应聘、预约、发布和聊天等行为需要登录。

核心产品原则：减少重复填写，但不打乱用户的自然表单顺序。档案只在表单进行到相应步骤时提供默认值，并在发布成功后才自动保存或更新。

## 2. 项目目标与成功标准

### 2.1 核心目标

- 帮助宠物主人快速发布结构化照护需求。
- 帮助服务者展示经验、服务范围、价格和可用时间，并管理多个服务。
- 根据地点、宠物、时间、任务和预算完成双向撮合。
- 通过站内消息完成咨询、应聘、预约和双方确认。
- 沉淀宠物、地图位置和服务档案，降低后续发布成本。
- 支持三种语言和多货币，为跨地区使用预留基础。

### 2.2 第一阶段成功标准

- 游客能够浏览附近需求、服务者和公开服务。
- 首次注册用户能够完成头像、昵称和首个发布引导。
- 非首次用户登录后直接进入个人中心，不被强制引导查看消息。
- 需求方与服务者能够分别完成申请或预约、沟通和确认闭环。
- 过期需求不再公开展示，但仍可在个人记录和收藏夹中查看。
- 发布成功后能够触发邮箱通知检查及匹配推荐。

## 3. 项目范围

### 3.1 本阶段包含

- 账号注册、登录、首次使用引导和个人中心。
- 个人资料、宠物档案、地图位置档案和服务档案。
- 三种需求模式和三种服务模式。
- 公开浏览、地图或列表展示、筛选、收藏和详情页。
- 站内聊天、咨询、应聘、预约和状态确认。
- 邮件消息通知、需求过期和匹配推荐。
- 三种语言切换及多货币基础。
- 服务单项管理和批量管理。
- 服务类型介绍及宠物照护知识链接库。

### 3.2 本阶段不包含

- 运营管理后台、举报投诉和平台仲裁。
- 实名认证、背景调查、平台保险和信用等级。
- 在线支付、平台抽佣、退款和赔付。
- 公开评价体系、视频通话和聊天自动翻译。
- 智能定价及复杂营销工具。

## 4. 用户角色与权限

| 角色 | 可执行操作 | 限制 |
| --- | --- | --- |
| 游客 | 浏览首页、附近需求、服务者、公开服务、详情、类型介绍和照护知识；切换语言 | 不能收藏、咨询、应聘、预约、发布和聊天 |
| 注册用户 | 编辑资料、管理宠物与地图位置、发布需求、收藏、咨询、应聘、预约和聊天 | 未开启接单模式时不能发布服务 |
| 服务者 | 拥有注册用户全部能力；建立服务档案、发布多个服务、处理预约、管理接单状态 | 关闭接单模式后，公开服务按规则暂停 |

同一账号可以同时拥有需求方和服务者能力，不创建互斥的角色账号。

## 5. 登录、注册与首次使用

### 5.1 首次注册

1. 用户完成账号注册和登录。
2. 引导用户完善头像和昵称。
3. 询问用户当前希望发布需求、提供服务，或暂时跳过。
4. 选择“发布需求”时，直接进入需求发布流程。
5. 选择“提供服务”时，先确认开启接单模式并创建服务档案，再选择服务类型。
6. 选择“暂时跳过”时，进入个人中心。

### 5.2 非首次登录

非首次用户登录成功后直接进入个人中心。

系统不弹出“是否查看新消息”的提示。用户自行选择消息中心、我的需求、我的服务、收藏夹、资料或设置等入口。

### 5.3 登录后返回原操作

游客从需求或服务详情触发收藏、咨询、应聘或预约时：

1. 进入登录或注册页面。
2. 登录成功后返回原详情页面。
3. 恢复登录前准备执行的操作。

## 6. 个人资料与可复用档案

### 6.1 基础资料

- 头像与昵称；
- 个人简介；
- 所在地区与大致地理位置；
- 常用语言；
- 绑定邮箱、验证状态和邮件通知开关。

### 6.2 宠物档案

每个用户可以创建多个宠物档案，包括：

- 名称、类型、品种、性别、年龄或生日；
- 体型、体重、是否绝育和照片；
- 性格、饮食、健康、过敏、用药和疫苗；
- 与人或其他动物的相处情况；
- 照护注意事项。

宠物健康、过敏和用药信息是完成照护所需的普通受保护资料，不按精确住址或正式医疗档案的高敏级别处理。用户自愿填写后，可在宠物档案、相关需求及已参与业务的用户界面按需展示，但不进入公开搜索摘要、邮件正文或普通日志。

### 6.3 地图位置档案

- 位置名称；
- 用户在地图选择的经纬度；
- 可选的国家、城市或区域显示标签；
- 是否设为默认位置。

平台不收集、保存或展示楼号、楼层、房号等精确家庭地址，也不设置确认后开放精确地址的流程。地点搜索文字只用于帮助地图选点，持久化数据以经纬度为准，不反向保存门牌级地址。

### 6.4 服务档案

- 个人介绍和照护经验；
- 擅长的宠物类型；
- 资质、证明及照片；
- 默认服务地点和服务范围；
- 常用货币单位；
- 接单模式状态；
- 全部服务批量管理入口。

## 7. 需求发布系统

### 7.1 通用表单与档案规则

1. 用户先选择上门、寄养或自定义需求，并按照该类型的正常顺序填写。
2. 表单进行到宠物步骤时读取宠物档案：有档案则选择，没有则在当前表单新建。
3. 用户继续填写时间、任务、物资或环境等当前类型内容。
4. 表单进行到地点步骤时读取默认地图位置：用户可以使用、切换或修改，没有则在地图选点。
5. 用户填写费用和其他后续信息，进入预览并确认发布。
6. 仅在发布成功后，将本次宠物资料和地图位置保存或更新到个人档案。

需求中的宠物和地图位置必须保存发布时快照。用户以后修改个人档案，不应改变已发布或历史需求。

### 7.2 上门需求字段

- 需要照护的宠物；
- 开始和结束日期；
- 每隔几天上门一次；
- 每个上门日需要几次；
- 每次期望时间段及可浮动范围；
- 每次对哪些宠物执行哪些任务；
- 喂食、换水、清洁、遛宠、陪伴、用药等任务；
- 服务地图位置；
- 总预算或按次预算；
- 是否支付交通费及其计算方式；
- 补充说明和紧急联系信息。

### 7.3 寄养需求字段

- 需要寄养的宠物；
- 寄养开始和结束时间；
- 宠物主人自带的物品；
- 寄养家庭需要准备的物品；
- 每只宠物每天的照护任务；
- 定期或不定期任务及执行时间；
- 期望的寄养环境；
- 不可接受的环境或情况；
- 是否允许寄养家庭存在其他宠物；
- 宠物接送方式；
- 出发地和可接受距离；
- 寄养预算；
- 物资费用和交通费用计算方式。

### 7.4 自定义需求字段

- 一个或多个宠物；
- 服务日期和时间；
- 服务地点；
- 任务及期望结果；
- 预算；
- 交通费或材料费；
- 补充说明。

### 7.5 需求状态

| 状态 | 公开展示 | 说明 |
| --- | --- | --- |
| 草稿 | 否 | 尚未发布，可继续编辑 |
| 公开招募中 | 是 | 未过期时可搜索、咨询和应聘 |
| 等待确认 | 视业务规则 | 已有申请进入重点沟通，但尚未成功 |
| 已找到服务者 | 否 | 发布者已确认某位服务者 |
| 已取消 | 否 | 发布者主动取消 |
| 已过期 | 否 | 超过有效时间，个人记录和收藏仍可查看 |
| 已完成 | 否 | 服务周期结束并归档 |

## 8. 服务档案与服务发布

### 8.1 开启接单模式

没有服务档案的用户首次发布服务时，平台提示：

> 确认开启接单模式吗？

确认后填写个人介绍和经验，再选择服务类型。已有服务档案时，直接读取现有资料。

### 8.2 表单内默认值规则

1. 用户选择服务类型并按正常顺序填写。
2. 到达服务地点步骤时读取服务档案；有默认地点则预填并允许修改，没有则填写新地点。
3. 用户继续填写服务内容、环境、证明、时间和限制条件。
4. 到达费用与货币步骤时读取常用货币；有则默认选中并允许修改，没有则选择。
5. 用户预览并确认发布。
6. 仅在发布成功后，将本次地点和货币保存或更新到服务档案。

### 8.3 上门服务字段

- 服务地点和服务半径；
- 可服务日期和每日时间段；
- 平日、周末和节假日可用情况；
- 日期范围和排除日期；
- 可服务宠物类型、体型和年龄；
- 相关经验、证明照片和服务任务；
- 单次服务时长；
- 收费方式和货币；
- 交通费和优惠；
- 可并行服务说明；上门服务不使用按宠物数量计算的寄养容量。

### 8.4 寄养服务字段

- 可寄养宠物类型、体型、年龄和日期；
- 寄养地图位置和服务范围；
- 寄养环境照片及居住环境；
- 家庭成员和环境中已有宠物；
- 庭院情况和可提供物资；
- 接待条件和限制；
- 单次最大宠物数量；
- 接送能力和范围；
- 收费、货币、物资费、交通费和优惠。

### 8.5 自定义服务字段

- 服务名称、时间和地点；
- 服务内容和宠物类型；
- 经验、照片和证明；
- 服务限制；
- 费用、货币和优惠。

### 8.6 服务管理

用户可以：

- 创建和管理多个服务；
- 编辑、暂停、开启或删除单个服务；
- 从服务档案暂停或开启全部服务；
- 批量修改全部服务地点或货币单位。

批量修改前必须展示受影响的服务，并要求用户二次确认。

## 9. 公开浏览、搜索与收藏

### 9.1 需求浏览

需求列表和地图显示：

- 需求类型；
- 宠物类型和数量；
- 大致地点；
- 服务日期；
- 预算；
- 主要任务；
- 发布时间；
- 是否支付交通费；
- 紧急程度。

支持按照以下条件筛选：

- 地点与距离；
- 预算与货币；
- 宠物类型与体型；
- 任务类别；
- 需求类型；
- 时间范围；
- 是否支付交通费；
- 排序方式。

### 9.2 服务与服务者浏览

列表显示服务者头像、昵称、大致地点、经验摘要、可服务宠物、公开服务和可用时间。

服务详情显示：

- 服务内容；
- 服务者资料；
- 服务地点与范围；
- 可用时间；
- 价格和优惠；
- 服务条件；
- 环境或证明照片；
- 所选日期已有的成功预约数量；
- 寄养服务的剩余宠物容量；上门和自定义服务不显示宠物容量。

### 9.3 收藏

登录用户可以收藏需求、服务和服务者。

收藏夹保留已过期需求，但必须显示“已过期”，并禁用咨询和应聘操作。

## 10. 咨询、应聘与预约

### 10.1 应聘需求

1. 用户在需求详情点击“应聘”；未登录时先登录并返回。
2. 系统检查应聘者是否有服务档案。
3. 有服务档案时提示发布者可以查看。
4. 没有服务档案时提示发布者通过聊天仔细了解对方经验。
5. 系统创建应聘申请及聊天会话，状态为“等待回复”。
6. 发布者可以确认、拒绝或继续沟通。
7. 只有发布者确认后，应聘才算成功。
8. 确认后需求变为“已找到服务者”，并从公开列表移除。
9. 发布者可以取消已确认服务者；需求未过期时可以重新公开。

### 10.2 预约服务

1. 用户在服务详情点击“预约”；未登录时先登录并返回。
2. 用户选择预约时间段。
3. 页面显示该日期已有的成功预约数量。
4. 系统检查服务状态和时间冲突；只有寄养服务额外检查按宠物数量计算的接待容量。
5. 提交后创建预约申请和聊天会话，状态为“等待服务者确认”。
6. 服务者可以确认、拒绝或继续沟通。
7. 只有服务者确认后，预约才算成功。
8. 成功后更新相应日期的预约数量；寄养预约同时更新剩余宠物容量。
9. 服务者可以取消确认，系统保留记录并通知预约用户。

## 11. 站内消息与邮箱通知

### 11.1 站内消息

会话来源包括：

- 需求咨询；
- 需求应聘；
- 服务咨询；
- 服务预约。

消息功能包括：

- 文本和图片；
- 需求卡片和服务卡片；
- 应聘和预约状态消息；
- 未读数量；
- 会话搜索；
- 系统状态消息。

### 11.2 发布后的邮箱通知检查

1. 需求或服务发布成功后检查邮箱通知状态。
2. 已经开启时不重复提示，直接进入推荐流程。
3. 未开启时询问用户是否接受在收到消息后立即发送邮件。
4. 用户接受时完成邮箱绑定或验证并开启通知。
5. 用户拒绝时不影响发布结果，继续进入推荐流程。

### 11.3 邮件发送规则

- 只向已验证邮箱且开启通知的用户发送。
- 覆盖新消息、应聘确认或拒绝、预约确认或拒绝、预约取消等重要变化。
- 连续消息采用短时间聚合，避免一条消息发送一封邮件。
- 用户可以在通知设置中随时关闭。

## 12. 生命周期与公开规则

### 12.1 需求公开条件

只有状态为“公开招募中”且未过期的需求，才进入首页、搜索、地图和匹配推荐。

### 12.2 自动过期

需求结束时间就是需求过期时间。系统以 `endDate` 判断是否过期；到达结束时间后：

- 从公开页面移除；
- 停止新的咨询和应聘；
- 不再参与匹配；
- 发布者仍可在“我的需求”中查看；
- 收藏者仍可在收藏夹查看；
- 历史聊天、申请和状态记录继续保留。

### 12.3 服务公开条件

服务需要同时满足：

- 服务处于公开接单状态；
- 服务档案接单模式开启；
- 满足可用时间条件；寄养服务还需满足宠物容量条件。

暂停、删除或全部关闭的服务不出现在公开列表。

## 13. 匹配与发布后推荐

### 13.1 需求匹配服务

匹配因素包括：

- 服务类型；
- 宠物类型、体型和年龄；
- 地点与距离；
- 日期与时间；
- 任务能力；
- 预算与货币；
- 寄养服务的宠物容量。

需求发布成功并完成邮箱通知检查后：

- 有高度匹配服务时，询问用户是否查看匹配服务。
- 没有完全匹配服务时，推荐能够照护相同宠物、但服务类别可能不同的其他服务。
- 用户暂不查看时，返回“我的需求详情”。

### 13.2 服务匹配需求

匹配因素包括：

- 服务类型；
- 服务地点和范围；
- 宠物类型；
- 日期；
- 任务；
- 预算；
- 服务限制。

服务发布成功并完成邮箱通知检查后：

- 有匹配需求时，可以查看匹配需求或附近需求。
- 没有完全匹配需求时，询问是否查看附近需求。
- 已过期、已取消或已找到服务者的需求不得推荐。

## 15. 核心数据模型

| 数据对象 | 职责 |
| --- | --- |
| `User` / `UserProfile` | 账号、基础资料、语言、地区和邮箱状态 |
| `PetProfile` | 可复用宠物档案 |
| `LocationProfile` | 可复用地图位置和默认位置，只保存经纬度及非精确显示标签 |
| `ProviderProfile` | 服务者介绍、经验、默认地点、服务范围和常用货币 |
| `Need` / `NeedPet` / `NeedTask` | 需求主记录、发布快照、关联宠物和任务 |
| `Service` / `Availability` / `BoardingCapacity` | 服务内容、可用时间，以及仅寄养使用的宠物容量 |
| `Application` | 需求应聘、确认、拒绝和取消记录 |
| `Booking` | 服务预约、时间段和状态；寄养预约记录宠物数量并占用容量 |
| `Conversation` / `Message` | 业务会话、用户消息和系统状态消息 |
| `Favorite` | 需求、服务及服务者收藏 |
| `NotificationPreference` | 邮箱绑定、验证和通知偏好 |
| `KnowledgeLink` | 照护知识标题、摘要、分类和链接 |

发布内容必须保留独立快照，避免个人档案后续修改影响历史业务记录。

## 16. 多语言与多货币

### 16.1 多语言

第一阶段建议支持：

- 简体中文；
- 英文；
- 日文。

页面、表单字段、按钮、状态、系统消息和邮件模板全部使用国际化键值管理。

用户生成内容和聊天内容暂不自动翻译。

### 16.2 多货币

- 服务档案保存常用货币，单个服务允许修改。
- 需求预算必须明确记录货币。
- 筛选和匹配同时考虑金额及货币。
- 第一阶段不强制自动汇率换算。
- 页面始终明确显示货币代码或符号。

## 17. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 响应式 | 优先适配手机浏览器，同时支持桌面和平板；长表单分步填写并自动保存草稿 |
| 性能 | 列表分页或范围加载、图片缩略与压缩、消息未读及时更新、过期和公开状态同步 |
| 隐私 | 平台不收集楼号、楼层、房号等精确住址；只保存地图坐标和非精确标签；聊天仅双方可见；历史业务保留必要快照 |
| 可用性 | 档案默认值允许修改；步骤切换不丢数据；发布前预览；状态文案清晰 |
| 可靠性 | 应聘和预约确认需要幂等；寄养宠物容量更新防止并发超额；邮件可重试但不能重复轰炸 |
| 可访问性 | 表单有明确标签、键盘可操作、状态不只依赖颜色、图片提供替代文本 |

## 19. 验收标准

- 游客可以浏览公开页面；触发受限操作后登录并返回原操作。
- 首次注册用户按照选择进入需求或服务流程。
- 非首次用户登录后直接进入个人中心。
- 需求表单只在宠物和地图位置步骤读取档案，发布成功后才写入档案。
- 服务表单只在地点和货币步骤读取服务档案，发布成功后才写入。
- 需求发布后执行邮箱通知检查，再进行服务推荐。
- 服务发布后执行邮箱通知检查，再进行需求推荐。
- 应聘和预约在对方确认前均不得显示为成功。
- 确认服务者后需求退出公开列表；取消确认且未过期时可以恢复公开。
- 服务详情可以展示所选日期成功预约数量；寄养服务按照宠物容量阻止超额接待。
- 过期需求不公开、不参与匹配，但个人记录和收藏仍可查看。
- 三种语言的页面文案、状态和邮件模板无遗漏。

## 20. 关键风险与控制

| 风险 | 等级 | 控制措施 |
| --- | --- | --- |
| 旧精确地址文本继续被采集或返回 | 高 | 新流程只接受地图坐标；API 拒绝门牌级字段；旧字段停止写入并安排清理 |
| 档案覆盖历史记录 | 高 | 需求和服务保存发布快照；发布成功后再更新默认档案 |
| 寄养宠物容量超额 | 高 | 提交与确认时按预约宠物数量双重检查；确认操作采用事务和幂等控制 |
| 状态不一致 | 高 | 建立显式状态机；所有关键变化写入系统消息与审计记录 |
| 邮件过度发送 | 中 | 验证邮箱、用户开关、消息聚合、退订和频率限制 |
| 长表单流失 | 中 | 分步表单、草稿、档案复用、进度提示和返回不丢数据 |
| 跨货币误解 | 中 | 金额始终携带货币；首期不隐藏换算假设 |
