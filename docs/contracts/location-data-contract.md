# T06 地图位置与数据最小化合同

## 存储合同

`MapLocation` 仅允许：

- `lat`：-90 到 90 的有限数值。
- `lon`：-180 到 180 的有限数值。
- `regionLabel?`：最多 120 字的非精确区域/车站/行政区标签。
- `displayPrecision`：CITY、DISTRICT、NEIGHBORHOOD 或 MAP_POINT。

输入使用 strict Zod object。楼号、楼层、房号、单元、门禁、到达说明、完整反向地理编码文本，以及任何未声明字段均拒绝。搜索框的查询文字只用于调用地理搜索和选点，不作为业务数据保存。

## 四类位置

| 类型 | 来源 | 更新时机 | 是否影响历史 |
|---|---|---|---|
| UserLocation | 个人常用地图点 | 用户编辑，或需求发布成功后明确 upsert | 否 |
| Provider defaultLocation | 服务档案默认地图点 | 用户编辑，或服务发布成功后 upsert | 否 |
| Need locationSnapshot | 发布时选择的地图点 | 发布事务内固定 | 不随默认值变化 |
| Service locationSnapshot | 发布时选择的地图点 | 发布事务内固定 | 不随默认值/批量修改历史预约变化 |

## 可见性

| 场景 | 坐标 | regionLabel | 禁止内容 |
|---|---|---|---|
| 所有者编辑 | 完整选点坐标 | 可见 | 搜索原文、门牌信息 |
| 公开列表/详情 | 约到小数点后 2 位的近似坐标 | 可见 | 完整坐标、旧 Raw 文本 |
| 已确认业务双方 | 任务快照完整坐标 | 可见 | 平台未收集的门牌信息 |
| 日志/分析/邮件 | 不记录 | 最多行政区级聚合 | 坐标、搜索词、照护健康内容 |

## API 行为

1. 地区或车站搜索返回候选点；浏览器只提交用户最终选择的 `MapLocation`。
2. 若地图服务不可用，允许从缓存行政区/车站选择后获得中心点，不退回自由文本地址保存。
3. 公开 DTO 只能由 `toPublicMapLocation` 生成，不能直接序列化数据库 location。
4. 发布事务成功后才 upsert 默认位置；事务失败不得产生半成品档案。
5. 旧 Raw 字段立即停止新流程写入；兼容读取仅在 mapper 内，迁移不复制原文。

## 自验收

- [x] 默认值与业务快照分离，发布失败不写回默认值。
- [x] 地图失败不以保存文字地址作为回退。
