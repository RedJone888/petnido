# ADR-002：旧数据非破坏性迁移

- 状态：Accepted
- 日期：2026-08-04

## 背景

线上现有 6 个用户、11 条需求、4 条服务，Application/Booking/Message 为 0。现有页面、API 和 schema 相互并不完全匹配，不能以任何一层直接覆盖其他层。

## 决策

采用 Expand → Dry-run → Backfill → Dual-read/write → Cutover → Contract。第一批只做目标草案和试验链路，不运行生产写迁移。

## 阶段门槛

1. Expand：只新增 nullable 列/新表/索引，不改旧列语义。
2. Dry-run：输出数量、无法映射原因、金额舍入差异，不输出内容和位置。
3. Backfill：固定批次和 checkpoint；源/目标数量、外键、唯一键全部对账。
4. Dual：新写路径写目标模型和必要旧兼容列；后台对比读取结果。
5. Cutover：按 feature flag 切换，失败只回滚应用读写，不删除新数据。
6. Contract：稳定至少一个发布周期并完成备份/恢复演练后，停止旧读并另行批准删除。

## 特殊规则

- 旧 Raw 位置文本不进入新模型，只复制合法坐标；非精确标签由坐标重新生成。
- 旧 NeedPet 不足以可靠创建 Pet 档案，不推测关联；只生成快照并记录未关联原因。
- Float 金额必须先输出舍入差异；按币种小数位转换，不直接 cast。
- 物理删除改为 archive/匿名化；历史预约和会话保持引用稳定。
- migration 脚本必须可重入、带版本、默认 dry-run，且拒绝在没有显式生产授权时写入。

## 回滚

数据库只向前扩展；回滚通过关闭 flag、停止双写、恢复旧读取完成。已经合法写入的新业务数据不删除，待修复后重放或转换。

## 自验收

- [x] 每个阶段有进入条件、对账和应用回滚方式。
- [x] 明确本批不写生产、不迁移旧位置文本、不猜宠物关系。
- [x] 线上现有记录分布已纳入风险判断。
