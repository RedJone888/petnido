# T01 两套需求发布流程对比

| 维度 | `/needs/create` 引导流程 | `/dashboard/needs/new` 旧流程 | 决策 |
|---|---|---|---|
| 三种模式 | 内容丰富，接近计划书 | 字段较少 | 采用引导流程 |
| 草稿 | localStorage v3 | 无完整恢复机制 | 保留并增加服务端草稿 |
| 预览 | 有独立预览页 | 无 | 保留 |
| 发布持久化 | 未调用后端，仅清草稿并提示成功 | 调用 `createNeed` | 把真实 mutation 接到引导流程 |
| 登录回跳 | 支持 `?restore=auth` 和 URL 回跳 | 登录区内页面 | 扩展为“回跳 URL + 待执行动作/草稿 ID” |
| 宠物档案 | 表单内录入，未可靠写回档案 | 旧字段结构 | 到宠物步骤读取档案；成功后 upsert |
| 地图位置 | 保存区域文本和坐标 | 保存 `addressRaw` 和坐标 | 只持久化经纬度及可选非精确区域标签 |
| 到期规则 | 有开始/结束日期 | 有开始/结束日期 | `endDate` 即公开到期时间 |
| 后续推荐 | 无 | 无 | 发布后执行匹配与降级推荐 |
| 邮件通知引导 | 无 | 无 | 成功页检测通知偏好并询问开启 |

## 合并策略

1. `/needs/create` 成为唯一正式的新建入口。
2. 复用旧流程的 tRPC/Prisma 调用思路，但不直接复用不匹配的输入结构。
3. `/dashboard/needs/new` 在新垂直切片稳定前保留为 feature flag 回退；之后重定向并移除旧表单。
4. 编辑流程复用新的步骤组件，并支持从已保存快照初始化。
